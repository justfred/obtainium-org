Excel file opens empty: diagnose, recover, prevent

Use when: a client opens an older Excel file (recent Excel, Windows) and the data appears to be gone. Rule one: don’t save, and work on a copy. Saving an “empty” view can overwrite what’s left. Updated: 2026-11-07

At a glance

  1. Is the data in the file? Size + zip test (Part 1). Big file = recoverable.
  2. If yes: find out whether it’s hidden (Part 2) or was cleared or blanked on open (Part 3).
  3. If no or tiny: go to versions and backups (Part 4).
  4. Record evidence (Part 5), pick the next step (Part 6).
  5. Then prevent a repeat (Part 7). Known reports are in Part 8.

Part 1. Is the data actually in the file? (2 minutes)

  • [ ] File size (right-click > Properties). Hundreds of KB or more = data almost certainly present. A few KB (an empty .xlsx is about 12 KB) or 0 KB = truly empty or a cloud placeholder (Part 4).
  • [ ] Zip test (.xlsx/.xlsm): copy the file, rename the copy to .zip, open it. Check xl/worksheets/sheet*.xml and xl/sharedStrings.xml. Large = data is there, so it’s a display or link problem and recoverable.
  • [ ] Old .xls: try LibreOffice or Google Sheets; either may read what Excel won’t.

Part 2. Is it hidden? (5 minutes)

  • [ ] Ctrl+End: where is the last used cell? Scroll there.
  • [ ] Hidden sheets: right-click a tab > Unhide. “Very hidden” sheets need the VBA editor (Alt+F11, Properties > Visible).
  • [ ] Hidden rows and columns; clear all filters (Data > Clear).
  • [ ] Hidden workbook window: View > Unhide.
  • [ ] Invisible text: white font, or custom number format ;;;. Select all, set a visible font color, set format to General.
  • [ ] Calculation mode: Formulas > Calculation Options > Automatic, then F9.

Part 3. Did something clear or replace it on open?

  • [ ] Update Links prompt declined or source path gone: Data > Edit Links. Formulas show 0 or #REF! when the source is missing.
  • [ ] Power Query, connections, pivots set to refresh on open: Data > Queries & Connections. A failed refresh can empty the result table. Open with refresh disabled or offline.
  • [ ] Macros: a Workbook_Open macro may clear ranges. Open with macros disabled (hold Shift while opening, or Trust Center), then inspect in Alt+F11.
  • [ ] Repair dialog (“found unreadable content”): note exactly what it said; content may have been dropped. Keep the original; try Open > Open and Repair > Extract Data.
  • [ ] Protected View or blocked file: Enable Editing, or unblock in file Properties.
  • [ ] Blank window or grey screen (no workbook shown at all): usually add-ins, file associations, or a hidden window, not data loss. Open via File > Open, test with excel /safe, disable add-ins one at a time, try Online Repair of Microsoft 365. See Microsoft’s troubleshooting article.

Part 4. Sync, storage, versions

  • [ ] OneDrive/SharePoint/Dropbox: is it a cloud-only placeholder or a sync-conflict copy (name has the computer name or “-conflict”)?
  • [ ] Version history (OneDrive/SharePoint: right-click > Version history). Windows: Previous Versions. Mac: Time Machine. A file reverted to an old version with sheets missing has been recovered this way.
  • [ ] File > Info > Manage Workbook > Recover Unsaved Workbooks; check the AutoRecover folder and %temp%. With AutoSave on, there may be no local AutoRecover copy.
  • [ ] OneDrive recycle bin and any other device’s sync folder.
  • [ ] Backups: compare size and modified date with the last good copy.

Part 5. Evidence to record (for the client and for you)

  • [ ] File name, path, size, created, modified, last saved by
  • [ ] Excel version, build, and update channel (File > Account > About Excel); platform of the client and of anyone for whom it opens fine
  • [ ] Where the file lives (local, file server, OneDrive/SharePoint) and whether AutoSave was on
  • [ ] Exact text of any prompt (links, macros, repair)
  • [ ] Zip-test result (sheet XML sizes)
  • [ ] Windows Application event log entries around the time
  • [ ] Which version or backup, if any, still has the data

Part 6. Decision

Finding Next step
Large file, data hidden or invisible Unhide, restore formatting, save a new copy
Large file, links or queries blanked it Repoint or disable the sources; extract values from the XML if needed
Macro cleared it Disable macro, recover from the earlier version
Repair dropped content Open and Repair > Extract Data; pull from the XML; use backups
Tiny or 0 KB file Version history, backups, AutoRecover, OneDrive recycle bin
Reverted to older state, sheets missing Walk back through version history for a version that has everything
Opens fine elsewhere Client-side issue: version, Trust Center, add-ins, profile

Part 7. Prevention

Root cause varies, so the aim is layers that make any cause recoverable and visible.

Recover

  • [ ] Versions, not just copies: OneDrive/SharePoint version history, or Windows Previous Versions/VSS on the file server, plus a real backup with weeks to months of retention. Sync alone copies an empty file as faithfully as a good one.
  • [ ] Second medium: import important workbooks into Google Sheets, either as an automatic mirror (Google Drive for desktop) or as dated copies. It’s a different vendor and format, with its own always-on version history, so one Excel failure mode can’t hit both. It loses macros, Power Query, and some formatting and pivot fidelity, so keep the original .xlsx too. Test with a few real files first and compare cell by cell. A mirrored .xlsx alone is just another sync copy.
  • [ ] Archive: monthly or quarterly dated read-only copies of important workbooks, plus CSV or PDF exports of the key data.

Settings and habits

  • [ ] AutoRecover: every 1–5 minutes, with “Keep the last autosaved version if I close without saving.”
  • [ ] AutoSave on cloud files commits a bad state within seconds. Use it only with version history on.
  • [ ] Old files: open read-only or in Protected View; convert legacy .xls to .xlsx once and keep the original.

Design

  • [ ] Avoid refresh-on-open links, queries, and macros on important files; keep a values-only copy of the data.
  • [ ] Raw data on its own sheet, as Excel Tables, separate from reports.
  • [ ] Long term, real data in a database or SharePoint list, with Excel as the viewer. Or Google Sheets as the primary for shared, simple data (weaker for heavy formulas, macros, large files).

Detect

  • [ ] A Control sheet with a row count or checksum against an expected value, so an emptied file is obvious on open.
  • [ ] Backup alert on a sharp file-size drop.

Environment

  • [ ] Check antivirus/EDR and Controlled Folder Access; test with excel /safe.
  • [ ] Record the Office build and channel and see whether cases cluster around an update.

Next time it happens: don’t resave; keep the file and the zip-test result (Part 5); submit via Feedback Hub or Microsoft support with the file and build number. Two or three captured cases will likely show a pattern.

Part 8. Known reports (web check, 2026-11-07)

No official Microsoft acknowledgment of a bug that empties recent Excel files was found. The evidence is user reports, so treat it as a pattern to watch.

  • AutoSave plus OneDrive is the leading suspect: files returning empty or partial, with no local AutoRecover copy to fall back on (one user’s account, unconfirmed). r/excel thread
  • Lost days of work after an update with AutoSave on; a moderator cited a known Excel/OneDrive sync-merge problem and advised restoring an older version. Microsoft Q&A
  • Reverted file, sheets missing, recovered from version history (same thread family).
  • Unverified (titles only): xlsm formulas stripped by repair after the March 2026 security update and workbooks corrupt after M365 Copilot summarize.
  • Older, acknowledged: a 2022 build made cells look blank or white. Office Watch
  • Microsoft’s own list: Fixes or workarounds for recent issues in Excel for Windows. Check it against the client’s build.

These concern recent saves. A client’s problem with old files may have a different cause, so don’t assume it’s the same.
